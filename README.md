# Mota 24 Optimality Lab

研究问题：能否对**一个精确指纹的胖老鼠 24 层 Flash 版本**，给出明确优化目标、完整规则和可独立验证的最优性证明？

**当前结果：已完成真实复刻地图的首个局部精确实验；尚未证明原版 24 层全局最优。**

本次里程碑 M3（2026-10-21）从真实源码和公开存档出发，不使用虚构地图。
此前提及的 M2 压缩包在当前机器不存在，旧对话只能恢复引用占位；本工程是透明重建，不声称继承了未取得的代码。

- 静态导出上游实际加载的数据：27 个地图对象、63 个敌人定义、50 个道具定义、88 种实际出现的图块 ID；保留所有楼层事件及来源。
- 两份 SWF 实际下载、SHA256、格式版本、内部矢量标题和静态脚本证据。
- MHHF 候选内嵌标题 **Ver 1.12**；27 张 11×11 原版地图和 33 个初始敌人数值表已静态提取。
- 原版 33 个敌人的五元组（HP、攻击、防御、金币、经验）全部能在复刻定义中找到匹配。这不表示战斗机制一致。
- 真实 MT1 最大出层 HP：**860**。事件搜索穷尽 832 个标签，逐格独立枚举穷尽 85,187 个完整状态，答案一致。
- CI 固定上游提交并重新导出、校验、搜索。没有提交原版 SWF、图片、声音或完整游戏文本。

## 快速复现

需要 Node.js 22+、Python 3.12+、Git。首次复现需要连接 GitHub 和 npm。

```sh
npm ci --ignore-scripts
npm run bootstrap
npm test
npm run experiment
```

`bootstrap` 只获取固定提交并用 Acorn 解析语法树，**不导入、eval 或运行上游游戏代码**。
生成完整 `generated/tower.json`、`generated/remake-baseline.json`；实验结果在 `generated/mt1.json`。
`experiments/` 保存已提交的数值记录和回归基线。耗时与峰值内存依赖机器，状态数、路线和答案是确定性的。

## 实验到底证明了什么

目标是从 MT0 开场事件后的初始能力（1000 HP、10 攻、10 防、三色钥匙各 1）进入 MT1，**不去其他楼层绕行**，首次踏上通往 MT2 的楼梯时最大化 HP。

本地测量：832 个展开标签、3,100 次可行动作转移、约 0.04 秒、约 27.4 MiB 进程峰值 RSS；最优范围 `[860,860]`。
独立逐格求解器保留精确 HP，不使用区域压缩或 HP 支配剪枝，得到相同结果。
每次有意义的动作消耗一个尚未消费的敌人/道具/门位；所有当前敌人为普通敌人、战斗伤害不依赖当前 HP，因此同一消费集合和连通区域中只保留最高 HP 是安全的。

这一局部目标的最优路线会花掉红钥匙。**最大化一层出层 HP 不是全塔最优策略**，更不是原版最优。
原版存在等级相关暴击；所下载 v1.12 候选代码还含计时门槛。两者没有加入本次 MT1 模型。
