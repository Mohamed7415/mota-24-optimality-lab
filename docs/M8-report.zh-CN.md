# M8：真实地图跨层优化搜索与原版路线验证

本阶段实际运行了前三层受限模型的搜索，并让原版完整影片执行胜出路线。固定 M6 开场后，回到一层的可行 HP 从 M7 路线的 **905 提高到 2150**。这不是三层或24层最优值。

这是**固定开场、固定种子、排除未验证事件的续程模型**，不是完整前三层玩法。任意原版三层或全塔路线的上界不能使用本阶段的13,860。

## 算法与实际搜索量

状态保留消费位集、跨层可达区域、HP、攻击、防御、三种钥匙、金币、经验、精确RNG状态。楼梯往返和空地行走压缩为可达区域；初始化时检查每条内部楼梯的反向入口几何，不满足则拒绝使用区域压缩。

相同位集、区域、全部非HP资源及RNG状态下，普通战斗成本固定，准入随HP单调，因此较高HP支配较低HP。商店会改变攻击/防御/金币，不能再假定消费位集单独决定这些资源。

实际使用确定性束搜索：宽1024、深度上限140，每层按
`HP + 60*攻 + 90*防 + 28*金币 + 80*黄钥匙 + 160*蓝钥匙 + 300*红钥匙`
选取候选。这个评分及束宽裁剪不保持完备；程序始终输出 `complete=false`。

内存是 Python 进程生命周期峰值，包含缓存，排除后续浏览器和其他子进程。耗时/内存依环境变化；稳定基准核对状态计数、路线、资源和抽样，不要求耗时一致。结束原因是保留前沿耗尽；此前丢弃过91,589项，**不能据此宣布穷尽**。

## 有限性与保守上界

初态后的前三层共有105个可消费事件；把无法抵达的事件也算上，总金币预算至多273，最多可买10次商店升级。因此任一路径最多有105+10=115次资源改变动作；140的深度上限没有排除合法的资源改变路径，束宽仍然排除了路径。

令 `N=105`、`B=273`，定义整数秩

`R = (N - popcount(mask))*(B+1) + 金币`。

始终有 `0 <= 金币 <= B`。消费一个事件会使第一项至少下降B+1，金币增加至多B；成功购买下降25金币。因此每个模型动作严格降低非负整数R。空地、楼梯、失败购买和菜单动作被压缩。资源来自有限的一次性事件，HP、攻防、钥匙、经验以及32位RNG均有有限范围，从而这个受限模型有限。这个论证没有覆盖全塔复生、剧情奖励、其他商店或真实时钟。

忽略伤害、门槛和可达性，将全部金币只用于回血：

`HP上界 = 860 + 剩余血瓶5000 + floor(273/25)*800 = 13,860`。

每次购买攻防都会减少可用于回血的预算，不会直接增加HP；所有战斗伤害非负。因此它是受限模型的保守上界。当前仅有区间 **[2150, 13,860]**，上下界远未相遇。

## 原版实际执行与独立校验

胜出续程50个事件/楼梯动作：37个消费事件、11次跨层、2次各25金币的800HP购买。收集铁剑、红/蓝宝石等；最终一层 HP2150、攻26、防13，黄/蓝/红钥匙6/1/1，金币0、经验47。

- 从原版标题菜单开始，总共585个普通鼠标/键盘输入，20场战斗、144次实际RNG抽样。
- 21次开场抽样加123次续程抽样逐项等于搜索预测；没有随机数跳过或游戏状态写入。
- 在独立官方 Ruffle 中执行未修改原版 SWF；观测器只读，原版游戏函数、音效、动画和界面实际运行。
- 再以相同输入顺序直接加载顶层原版，不使用观测器，不读写游戏变量；结束等级/属性/钥匙/楼层四个显示区域逐像素一致。
- 所有42个已消费格在多次往返后仍为0，未重复领取资源。
- 独立逐格路线校验用逐层 BFS 和既有帧级战斗模型，不导入束搜索、区域图、支配键或快捷战斗函数；核对50动作、500个移动/接触步骤、123次续程抽样及最终资源。它验证路线，不穷尽最优解。
