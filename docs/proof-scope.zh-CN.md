# 全局最优性：目标、有限状态假设与当前证明边界

M4 更新：已增加原版字节码子集差分验证及原版 MT1 的两个条件模型，见 [M4 报告](M4-report.zh-CN.md)。本文的复刻 MT1 证明作为 M3 历史结果保留；原版全塔、实际 PRNG 和原生播放器回放仍未完成。

## 先定义“最优”

对固定 SWF 指纹和结束条件，下面是不同的问题，不能互换：

| 目标 | 随机数约定 | 应交付的证明 |
|---|---|---|
| 理论可能的最高结束 HP | 允许合法随机结果，不准改存档/内存 | 最好情况上下界与可实现路径 |
| 可保证的最高 HP | 随机结果视为对手选择 | 保证值与策略 |
| 最大期望 HP | 忠实概率分布与可观察信息 | MDP 策略及期望证明 |
| 最少步数/最短时间 | 明确移动、动画、等待、计时 | 指定结束条件的最短路径证书 |
| 最高等级/得分 | 规定评分函数或优先顺序 | 同一目标下的上下界 |

最高 HP、最高等级、杀死血影、挑战魔龙不构成同一个目标。复刻新增的 200 级真结局不自动成为 Flash 的结束条件。
存读档、反复重开挑随机、编辑存档、时间操纵也必须在策略规则中说明。

所取得 v1.12 候选有 `random(200)`、`kill_max <= Now_life`，双倍分支作用于勇士伤害。
若随机值为 0..199，等级 1 也能走进暴击分支，因此不能等同于无暴击模型。
本阶段尚未把 RNG 实现、随机序列可达性当作已验证规则。

## 当前已证的有限模型

复刻 MT1 首次进入 MT2 时最大化 HP，禁止其他楼层绕行。
初始 HP 1000、攻防各 10、三色钥匙各 1；钥匙来自静态读取的 MT0 开场三个 setValue。

- 地图 13×13；43 个敌人/道具/门消费位；每个有意义动作恰好增加一位。
- 所有当前敌人 special=0，魔防 0；楼层事件与各种后置脚本为空。
- 道具、敌人、门各消费一次；走已清空道路不改变目标或资源。
- 消费集合固定攻击、防御、钥匙、金币和经验；HP 可以因战斗顺序而异。
- 普通敌人伤害不依赖当前 HP。因此同一消费集合、同一清空区域内，高 HP 标签能模拟低 HP 标签未来动作，可以安全支配。

位集粗界 `2^43 = 8,796,093,022,208` 不是实际状态数；HP 粗上界 2900 来自初始值加全部回血道具，并非人为截断。
资源均由有限消费集合决定，所以该模型有限。

事件前沿穷尽 832 个标签，独立逐格枚举穷尽 85,187 个完整状态（精确 HP、无区域压缩/支配），答案都为 860。
`[860,860]` 仅是这个模型的最优区间。路线回放核对可达性、资源、伤害，不是 Flash 引擎动态差分回放。

## 原版全局模型仍须证明的前提

1. 无敌人复生、重复奖励、道具复取、商店正收益循环，或对这些循环已有完备建模。
2. 地图变化、剧情旗标、敌人数值阶段、结束条件全部进入状态。
3. HP/攻防乘法、取整、浮点和 AVM1 数值转换忠实。
4. 墙、门、飞行、工具、商店等所有动作的条件与效果齐全。
5. 时钟离散化、午夜、保存读取、动画、等待不会遗漏可行策略。
6. 随机数分布、内部状态和可观察性明确。
7. 目标上界有限，所有剪枝对指定目标保持完备。

本候选代码用 1800 秒门槛并修改 16 层地图，不能直接照抄网络“25 分钟”的说法。
`TimeRunId` 与 `TimeRunID` 也不能按现代 JavaScript 规则直接判成两个变量：
[Adobe 文档](https://open-flash.github.io/mirrors/learning-as2.pdf)说明 SWF6 及更早标识符不区分大小写。
动态计时行为仍待回放。

固定、有限且准确的状态图理论上可以穷举求最优；可用资源内能否完成是另一个问题。
目前没有证据证明本作理论上不可求，也没有证据证明本工程已能求出原版全局答案。
Flash 真实数值表示有限，并不自动给出一个实用、忠实且可搜索的游戏状态抽象。
如果改用无界整数、允许任意存档或时间操作，须重新说明模型和有限性。

## 下一步验收条件

先使原版战斗、开场、移动与常见道具逐步一致性可重复验证，再扩展商店、特殊伤害、动态敌人、剧情、隐藏层与时钟。
每个结果绑定 SWF SHA256、规则版本、目标、初态、结束条件、上下界；仅当界限相遇且建模/剪枝前提成立时，才能宣布原版全局最优。
