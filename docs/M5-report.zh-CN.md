# M5 阶段报告：固定 Ruffle 的随机数约束与原版一层上界

日期：2026-10-22。公开仓库：[mota-24-optimality-lab](https://github.com/Mohamed7415/mota-24-optimality-lab)。

## 本次实际结果

**将 M4 的原版一层局部上界从 995 HP 收紧至 980 HP。**
这是固定 Ruffle 0.7.1、采用 M4 局部规则且连续战斗抽样之间没有额外 RNG 调用时的条件上界。
980 是一个允许额外随机序列的放宽模型的精确最优值；尚未找到或证明真实种子可达到 980。
原版 24 层全局最优、Adobe 原生播放器行为、整部原版游戏的按键回放仍未完成。

这次推进解决了 M4 的一个实质问题：不能把每次 `random(200)` 都当成独立、任意可选的结果。
M4 的 995 在它自己的独立支持模型中仍正确；在本次更具体的条件模型中已被排除。
它不是仅仅因为原有见证路线不成立而被排除，而是因为新的上界对所有局部路线都成立。

## 完整 RNG 状态枚举

该版本每次抽样先做 `T(s) = (s >> 1) XOR (s 为奇数时的 0x48000000)`，再作固定的 32 位散列。
无论初始种子为哪个 32 位数，第一次 T 后状态位于 0..2^31−1。
非零的 31 位状态经 T 后不会变为零；零态输出为 109，不能延长暴击串，即使下一次使用重新播种。

C 程序用无符号整数与显式算术右移实现散列，完整检查 **2,147,483,647 个非零状态**。
固定等级 1，输出 0 或 1 时暴击；最大连续暴击数为 **4**，没有 5 连暴击起点。
各起点恰有 0/1/2/3/4 次开头暴击的数量分别为：
`2,126,004,609 / 21,264,391 / 212,504 / 2,124 / 19`，总和等于检查范围。
见证起点 `121448050` 的四个暴击输出及后继非暴击数值列于实验 JSON。
本机完整枚举 CPU 耗时约 3.5 秒，具体原始计时保留在基准中。

这仍以算法移植、编译器和运行时正确为可信基础，不是证明助理内的机器形式化证明。
也没有将此结果推广为所有 Adobe Flash Player 的 RNG 定理。

## 从 RNG 约束到 980 上界

仍然固定：原版 MT1、初始 1000HP/10攻/10防、1级、三色钥匙各1、首次触及上楼梯为终点；不跨层绕行、不进商店。

把随机历史压缩为末尾连续暴击数 0..4；普通攻击将其清零，暴击使其加一，禁止从4再次暴击。
这个自动机允许许多真实 RNG 不会产生的序列，却包含所有满足上述抽样约定的真实序列，因此它的最优值是上界。
战斗间保留末尾计数，拾物、移动和开门不重置。

每场战斗针对每个末尾计数分别求最少攻击次数；相同末尾计数下，多挨打不能改善未来，因此可以保留最高HP。
事件搜索键为已消费对象集合、已清空连通区域、末尾暴击数。集合固定其余资源，准入对HP单调，故高HP标签可安全支配低HP标签。
每个事件至少消费一个对象，状态图有限，穷尽结果为980。

| 算法 | 完整搜索量 | 本机耗时 |
|---|---:|---:|
| 事件前沿 + HP 支配 | 2,032 个展开标签，12,278 条生成转移 | 约0.29秒 |
| 独立逐格 + 精确HP，无地图状态间HP支配/区域压缩 | 727,668 个完整状态 | 约0.61秒 |

独立逐格实现先穷举单场战斗所有攻击次数/末尾计数，再按相同末尾计数取最少挨打次数；
它没有调用事件搜索的战斗 BFS 或图压缩逻辑。这项单场支配也由独立小规模穷举测试核对。
最初尝试在逐格状态中保留全部较差单场HP，超过300万状态限额；该尝试没有被当作完整验证。

完整 M5 驱动进程的本机峰值驻留内存约206 MiB，包含提取、事件搜索和独立逐格枚举；不是单一算法增量内存。
精确计时、内存与环境记录在 [M5实验 JSON](../experiments/ruffle-M5.json)。不同系统和编译器耗时会改变，数值结论需一致。

980 放宽模型的一条路线为：红门(5,8)、黄门(3,2)、骷髅(2,2)、血瓶(0,2)、红宝石(2,3)、
绿头怪(5,0)、红头怪(4,0)、绿头怪(3,0)、黄钥匙(2,0)，再触及上楼梯。
其中第一场攻击型态 `CCCCNCCCCNCC` 只是自动机见证，**没有声明真实 RNG 可实现**。

M4 的860保证策略仍提供本地规则内的保守保证；结合本次结果，可给这个条件模型的最优值保守夹在 `[860,980]`。
它既不是全塔区间，也不是固定真实种子的精确最优区间。

## 测试、自动化与尚未完成

本机运行4项 Node测试、29项Python测试，全通过（设置原版 SWF 环境变量后不跳过集成项）。
新增 CI 独立 Ruffle 作业会重新获取固定SWF/播放器、安装浏览器、完整枚举RNG状态、执行两组播放器探针、
交叉验证980并比较稳定基准。只上传数值JSON。

下一项实质验收应是：整部未改原版 SWF 的确定输入回放及可审计状态观测，明确所有 RNG 消费点、种子/等待/保存规则；
然后把商店、跨层、特殊敌人、剧情和时钟纳入状态。当前未发现这些任务客观不可完成，也未将它们宣称完成。
24层最高HP或其他目标必须先固定终点和随机策略，证明上下界相遇后才能宣布全局最优。
